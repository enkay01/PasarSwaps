# IBKR API options: TWS API on Trader Workstation, TWS API on IB Gateway, and the Client Portal Web API

Status: research finding
Evidence checked: 2026-09-16

## Which one to use

Point the TWS API at IB Gateway. Install Trader Workstation on the same machine too, for the first login and for checking data by hand.

IB Gateway and Trader Workstation are the same server from the API's point of view, and IB Gateway uses about 40% fewer resources. Neither supports a headless session, so a GUI process holds the login. Autorestart runs Monday through Saturday; the only manual step in the week is re-authentication after the Saturday night reset. Multi-leg orders are first-class through BAG contracts and ComboLeg objects, and reconnect logic is yours. [IB Gateway](https://ibkrcampus.com/docs/tws-api/doc/architecture/the-trader-workstation/the-ib-gateway) · [General third party FAQ](https://ibkrcampus.com/docs/third-party-integrations/general-third-party-frequently-asked-questions)

Reach for the Client Portal Web API only when you want the Client Portal's own view of an account. An individual runs the Java gateway, logs in through a browser on the same machine, and repeats that daily, and IBKR does not support automating that login. OAuth 2.0, which removes the local gateway, is limited to licensed organizations, financial advisors, and introducing brokers. [Installation and authentication](https://ibkrcampus.com/docs/web-api/authentication/cpgw/installation-authentication) · [OAuth 2.0 introduction](https://ibkrcampus.com/docs/web-api/authentication/oauth-2/introduction)

Both paths need a live, funded, IBKR Pro account, and the paper account is opened from it. [Paper Trading](https://ibkrcampus.com/docs/tws-api/doc/notes-limitations/limitations/paper-trading) · [Trading access for individuals](https://ibkrcampus.com/docs/web-api/trading/getting-started/trading-access-for-individuals)

## What will bite you

Use a separate username for the API if you want unattended reconnect. One trading application at a time per username is allowed, and a Client Portal login on the same username stops TWS or IB Gateway reconnecting automatically after the next disconnect. One TWS session accepts up to 32 simultaneous API client connections; client ID 0 also sees orders from TWS and FIX, and another client id can be set as the Master Client ID to see all orders. [Logging into multiple applications](https://ibkrcampus.com/docs/tws-api/doc/connectivity/logging-into-multiple-applications) · [Synchronous connect and start](https://ibkrcampus.com/docs/tws-api/doc/synchronous-api/connect-start-connection) · [ClientId 0 and the master client ID](https://ibkrcampus.com/docs/tws-api/doc/order-management/client-id-0-and-the-master-client-id)

Ports are defaults, not fixed values: TWS live 7496, TWS paper 7497, IB Gateway live 4001, IB Gateway paper 4002. Read yours from config, and never guess which environment a port points at. The API does not know paper from live, so the safety of paper mode comes from the login and the account number reported at handshake. Check the account id at startup. [Synchronous connect and start](https://ibkrcampus.com/docs/tws-api/doc/synchronous-api/connect-start-connection) · [General third party FAQ](https://ibkrcampus.com/docs/third-party-integrations/general-third-party-frequently-asked-questions)

A paper account is a second username with its own password and account number, not a mode flag. It starts with USD 1,000,000 of Equity with Loan Value and can be reset to up to five times the production account value. Fills are simulated from the top of the book, and the documented gaps include no VWAP, Auction, RFQ, or Pegged to Market orders, limited combo trading, always simulated stops, and no mutual fund trading. Do not treat a paper combo fill as evidence a live combo would fill the same way. [Paper Trading Account](https://www.ibkrguides.com/clientportal/papertradingaccount.htm) · [About Paper Trading Accounts](https://www.ibkrguides.com/clientportal/aboutpapertradingaccounts.htm) · [Paper Trading](https://ibkrcampus.com/docs/tws-api/doc/notes-limitations/limitations/paper-trading)

An unattended bot meets a disclosure step: IBKR asks you to certify whether API messages come from an automated system and to name the software and the external operator. [Automation and software disclosure](https://ibkrcampus.com/docs/general/market-data-subscriptions/compliance-requirements-for-api-market-data/api-user-activity-certification/automation-and-software-disclosure)

Market data through the API is a paid subscription per username and needs the Market Data API acknowledgement, an opened IBKR Pro account, and USD 500 above the cost of the subscriptions. The TWS API can request live, frozen, delayed, or delayed frozen data, but delayed data only works with `reqMktData` and `reqHistoricalData`, not tick data. [Market data requirements](https://ibkrcampus.com/docs/general/market-data-subscriptions/market-data-requirements) · [Delayed market data](https://ibkrcampus.com/docs/tws-api/doc/market-data-delayed/introduction)

The Web API adds its own work. A session stays authenticated for up to 24 hours, times out after about six minutes without requests or a `/tickle` every five minutes, and a tickle every minute is recommended. If the brokerage session times out while the connection is up, `/iserver/auth/status` returns `connected: true` and `authenticated: false`, so poll both fields, and call `/iserver/auth/ssodh/init` to start a new session. Some order submissions also return a reply that must be confirmed with `POST /iserver/reply/{messageId}`, or the order stops at a confirmation prompt. [Authentication FAQ](https://ibkrcampus.com/docs/web-api/authentication/faq) · [Initialize brokerage session](https://ibkrcampus.com/docs/web-api/v1/endpoints/session/initialize-brokerage-session) · [Order reply messages](https://ibkrcampus.com/docs/web-api/trading/orders/order-reply-messages)

Order type coverage is not uniform: "Not all order types are available in both platforms." Confirm each order type on the API you target before designing around it. Fractional and cash quantity trading are not supported, with crypto and forex as the exceptions. Nothing beyond TWS is on the API either: "If a certain feature or operation is not available in the TWS, it will not be available on the API side either." Account management is not supported, so account settings stay a manual Client Portal job. [Order type by API](https://ibkrcampus.com/docs/general/order-types/notes-limitations/order-type-by-api) · [Order types, notes and limitations](https://ibkrcampus.com/docs/general/order-types/notes-limitations/introduction) · [TWS API limitations](https://ibkrcampus.com/docs/tws-api/doc/notes-limitations/limitations/introduction) · [Supported 2FA](https://ibkrcampus.com/docs/tws-api/doc/notes-limitations/supported-two-factor-authentication-2-fa)

Combo orders have one valid price shape. Two legs in a NonGuaranteed order can be priced per leg; three or more legs must be priced as one order and must not be NonGuaranteed. [Combo orders](https://ibkrcampus.com/docs/tws-api/doc/orders/place-order/combo-orders)

The official library ships with the TWS API installer, not on GitHub. The `InteractiveBrokers` org publishes one repository, `tws-api-public`, last updated in January 2018. IBKR acknowledges the community wrapper `ib_insync`, says it cannot support it, notes it is built on a legacy API release and is no longer updated, and points users to `ib_async`. A wrapper is a dependency with no IBKR support. [InteractiveBrokers GitHub org](https://github.com/InteractiveBrokers) · [ib_insync and ib_async](https://ibkrcampus.com/docs/tws-api/doc/third-party-api-platforms/non-standard-tws-api-languages-and-packages/ib-insync-and-ib-async)

Two gaps could block a build. There is no official table of which order types work on which API, so each one needs a manual check. The docs also do not say whether resting orders survive the TWS daily restart or a Web API session end, so reconcile orders after every reconnect.

## Reference: the three paths side by side

| Question | TWS API on Trader Workstation or IB Gateway | Client Portal Web API |
| --- | --- | --- |
| What runs locally | Trader Workstation or IB Gateway plus your client ([download](https://ibkrcampus.com/docs/tws-api/doc/download-tws-or-ib-gateway/download-tws-or-ib-gateway)) | Client Portal Gateway (Java) plus your client, for individual users ([installation](https://ibkrcampus.com/docs/web-api/authentication/cpgw/installation-authentication)) |
| Transport | TCP socket to the local host | HTTPS and websocket to the gateway, then IBKR |
| Login | Username and password typed into TWS or IB Gateway | Browser login at `https://localhost:5000` |
| 2FA | IB Key, Handy Key, SMS, DSC+. Code cards are not supported ([Supported 2FA](https://ibkrcampus.com/docs/tws-api/doc/notes-limitations/supported-two-factor-authentication-2-fa)) | Same |
| Unattended operation | No headless session, so a GUI process holds the login ([IB Gateway](https://ibkrcampus.com/docs/tws-api/doc/architecture/the-trader-workstation/the-ib-gateway)) | The gateway is headless but the login is not, and automating it is unsupported ([Client Portal Gateway FAQ](https://ibkrcampus.com/docs/web-api/authentication/cpgw/client-portal-gateway-faq)) |
| Daily restart | Built to restart daily; autorestart from version 974+ ([Daily and weekly reauthentication](https://ibkrcampus.com/docs/tws-api/doc/tws-settings/daily-weekly-reauthentication)) | Session lasts up to 24 hours and re-authentication is required daily ([Client Portal Gateway FAQ](https://ibkrcampus.com/docs/web-api/authentication/cpgw/client-portal-gateway-faq)) |
| Forced logout | Saturday night server reset needs credentials entered again; the weekly reauthentication cycle starts Monday ([IB Gateway](https://ibkrcampus.com/docs/tws-api/doc/architecture/the-trader-workstation/the-ib-gateway)) | `/iserver` is unavailable nightly around 01:00 local time by region; Web API maintenance is Saturday evening ([Scheduled server maintenance](https://ibkrcampus.com/docs/web-api/trading/usage-and-availability/scheduled-server-maintenance)) |
| Detecting and recovering a drop | `connectionClosed` and `isConnected` report the drop; reconnect is the client's job ([Broken API socket connection](https://ibkrcampus.com/docs/tws-api/doc/connectivity/broken-api-socket-connection)) | `/iserver/auth/status` reports `authenticated`; call `/tickle` each minute; `/iserver/auth/ssodh/init` starts a new brokerage session ([Authentication FAQ](https://ibkrcampus.com/docs/web-api/authentication/faq)) |
| One session per username | One trading application at a time per username; extra usernames are available ([Logging into multiple applications](https://ibkrcampus.com/docs/tws-api/doc/connectivity/logging-into-multiple-applications)) | One brokerage session across all IBKR platforms ([Session authentication](https://ibkrcampus.com/docs/web-api/authentication/sessions)) |
| Ports | Live 7496, paper 7497; IB Gateway live 4001, paper 4002. Defaults, not fixed values ([Synchronous connect and start](https://ibkrcampus.com/docs/tws-api/doc/synchronous-api/connect-start-connection)) | Not applicable |
| Paper against live | Log in with paper credentials. The API does not know which environment it is talking to ([General third party FAQ](https://ibkrcampus.com/docs/third-party-integrations/general-third-party-frequently-asked-questions)) | Separate paper username and password; there is no live or paper slider ([Using a paper account](https://ibkrcampus.com/docs/web-api/authentication/paper)) |
| Market data | Paid subscription per username; live, frozen, delayed, and delayed frozen are selectable from the API ([Delayed market data](https://ibkrcampus.com/docs/tws-api/doc/market-data-delayed/introduction)) | Same subscription rules. Snapshot and websocket top of book; history caps at 1000 data points ([Historical market data](https://ibkrcampus.com/docs/web-api/v1/endpoints/market-data/historical-market-data)) |
| Order types | Nearly full parity with Trader Workstation ([IBKR API home](https://ibkrcampus.com/docs)) | Not all order types. Each order type page lists the interfaces that support it ([Order type by API](https://ibkrcampus.com/docs/general/order-types/notes-limitations/order-type-by-api)) |
| Combos | BAG contract with ComboLeg. Only a two leg NonGuaranteed order can be priced per leg; three or more legs are priced as one order ([Combo orders](https://ibkrcampus.com/docs/tws-api/doc/orders/place-order/combo-orders), [Spreads in the TWS API](https://ibkrcampus.com/docs/general/contracts/spread-contracts/twsapi-spreads/spreads-in-the-tws-api)) | `conidex` string with a spread conid and a leg and ratio list. Leg count varies by exchange ([Orders for combos and spreads](https://ibkrcampus.com/docs/web-api/trading/orders/orders-for-combos-spreads)) |
| Asset classes | `secType` values: STK, OPT, FUT, IND, FOP, CASH, BAG, WAR, BOND, CMDTY, NEWS, FUND ([Contract reference](https://ibkrcampus.com/docs/tws-api/ref/contract)) | Docs show stocks, options, futures options, event contracts, and combos. No coverage matrix is published ([Finding options chains](https://ibkrcampus.com/docs/web-api/trading/instrument-discovery/finding-options-chains)) |
| SDKs and languages | Python, Java, C++, C#, VB.NET. C# and VB.NET are Windows only. Delivered by the TWS API installer, not as a package ([TWS API requirements](https://ibkrcampus.com/docs/tws-api/doc/notes-limitations/requirements)) | REST and websocket, so any HTTP client works. Docs give Python and curl examples. No official SDK |
| Pacing | 50 orders per second. Message pacing is configurable; breaking it three times ends the session ([Pacing behaviour](https://ibkrcampus.com/docs/tws-api/doc/pacing-limitations/pacing-behavior)) | 10 requests per second per username plus per-endpoint limits. `429` and a penalty box ([Web API pacing limitations](https://ibkrcampus.com/docs/web-api/trading/usage-and-availability/pacing-limitations)) |
| Main stated limits | No headless session, no account management, no fractional or cash quantity except crypto and forex ([TWS API limitations](https://ibkrcampus.com/docs/tws-api/doc/notes-limitations/limitations/introduction)) | Browser login and all calls on the gateway machine, no automated login, daily re-authentication ([Client Portal Gateway limitations](https://ibkrcampus.com/docs/web-api/authentication/cpgw/limitations-of-the-client-portal-gateway)) |
