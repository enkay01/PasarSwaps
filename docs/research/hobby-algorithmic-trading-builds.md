# Hobby algorithmic trading builds on YouTube

Status: research finding
Evidence checked: 2026-09-15

## The answer

For US stocks, the clearest repeated choice is Alpaca. It has a separate paper endpoint, a separate live endpoint, and a Python SDK, and Part Time Larry, Matt Macarty, Connor Create, The Code City, and Jacob Amaral all show it in stock projects. IBKR appears in projects that need more asset types or more broker features, and its API needs Trader Workstation or IB Gateway for many personal setups, which adds work at startup and during reconnects. Tradier appears in stock and option API tutorials. OANDA appears in forex bots, and Binance appears in crypto bots and in the crypto frameworks used by Hummingbot, Freqtrade, and OctoBot. The features that repeat across the builds are one strategy that can run in backtest and paper mode, saved orders and positions, a dry-run switch, account and provider status, logs, and a way to stop new orders. Risk and execution details are less consistent and need more research.

## What the repeated features imply

The features that show up across these projects point at the shape of a build. One strategy definition has to run in backtest and paper without a code change, which Freqtrade and Blankly both do. Orders, fills, positions and balances have to survive a restart, and provider state needs reconciling before any new order goes out, so a restart cannot place the same order twice. Risk limits belong in settings rather than in strategy code, and the set that repeats is position size, daily loss, drawdown, a maximum number of open positions, a stale-data rule and a switch to stop new orders. Every result should record which data source it ran on and when each observation became available, because a backtest over Yahoo data and a backtest over the broker feed are not the same test.

## What the sources do not show

A video title that says "live" is still only a claim until the source shows the account, order state, and fills, and several of the projects above stop at paper trading. Paper fills are not live fills, and a backtest chart or a "working bot" claim is not proof of profit. A provider named in an old tutorial may have changed its endpoint, permissions, rate limits, or data terms since, and Blankly still lists Coinbase Pro and FTX. One successful request is not proof of a connected account either, since authentication, market data, order submission, order updates, and reconciliation can each fail on their own.

## Reference detail

The feature set that repeats across the sources: Freqtrade documents backtest, dry-run, and live modes and ships protections, maximum open trades, SQLite persistence, WebUI, REST, and Telegram alerts ([strategy and mode docs](https://www.freqtrade.io/en/stable/strategy-101/)); Blankly describes the same strategy shape across backtest, paper, sandbox, and live; QuantTrader records sessions and ticks; OctoBot stores logs; Hummingbot has position-exit controls; and the [WalllerG paper bot](https://github.com/WalllerG/Automated-paper-trading-bot) has position sizing, drawdown limits, daily loss limits, single-instance locking, and persisted kill-switch state.

Provider paths a build would use. Alpaca paper uses `https://paper-api.alpaca.markets` with separate paper credentials and is a real-time simulation that omits market impact, latency slippage, queue position, price improvement, regulatory fees, and dividends, while live trading uses `https://api.alpaca.markets`, separate credentials, and Alpaca brokerage onboarding; free stock data is IEX, and full US market coverage needs a different data plan ([authentication](https://docs.alpaca.markets/us/docs/authentication), [paper trading](https://docs.alpaca.markets/us/docs/paper-trading), [account plans](https://docs.alpaca.markets/us/docs/account-plans), [market data](https://docs.alpaca.markets/us/docs/about-market-data-api)). Interactive Brokers paper accounts are linked to a live account, the API reaches either through TWS or IB Gateway, and paper fills are simulated with some order types behaving differently ([TWS setup](https://www.interactivebrokers.com/campus/trading-lessons/installing-configuring-tws-for-the-api/), [order types](https://www.interactivebrokers.com/campus/?p=195739&post_type=ibkr-api-page), [API overview](https://www.interactivebrokers.com/campus/ibkr-api-page/ibkr-api-home/)).

Tradier sandbox uses `https://sandbox.tradier.com/v1` with a paper token and delayed market data, production uses `https://api.tradier.com/v1`, and `preview=true` validates an order without submitting it; Tradier documents 60 requests per minute for sandbox trading and 120 requests per minute for production standard and market-data calls ([endpoints](https://docs.tradier.com/docs/endpoints), [trading](https://docs.tradier.com/docs/trading), [rate limits](https://docs.tradier.com/docs/rate-limiting)). OANDA practice runs on `https://api-fxpractice.oanda.com` and production on `https://api-fxtrade.oanda.com` ([development guide](https://developer.oanda.com/rest-live-v20/development-guide/), [introduction](https://developer.oanda.com/rest-live-v20/introduction/)). Binance spot testnet uses virtual funds under separate terms, and production APIs need separate trading and account permissions for each product, so a framework paper simulator is not Binance Testnet ([testnet terms](https://developers.binance.com/en/docs/products/spot/testnet/TESTNET-TERMS-OF-USE), [API introduction](https://developers.binance.com/en/docs/introduction), [spot REST](https://developers.binance.com/en/docs/products/spot/rest-api)).

Three projects carry a lower evidence grade. The [Joma Tech Twitch trading bot video](https://www.youtube.com/watch?v=-UdWguw90g4) is a public trading experiment on Interactive Brokers, but it is an audience-driven experiment, not a code-first hobby app reference. The [QuantDinger demo](https://www.youtube.com/watch?v=tNAZ9uMiUUw) and [source](https://github.com/OpenByteInc/QuantDinger) show a larger full-stack system with market feeds, strategies, backtests, live execution, workers, monitoring, trade logs, and audit logs, which is bigger than the app in this repo. The [LosingLoonies bot video](https://www.youtube.com/watch?v=DVVVvlK2O_k) is a personal project for Reddit signals and analysis, and its [site](https://losingloonies.ca/products) says its products do not connect to brokerage accounts, so it is not a paper or live execution example.
